## Decisions log

- 2026-10-13 — AI safeguards: `useAiRequest` per action (new requestId per action, reused only for a no-answer retry with the same input, never automatic); only interrupted/lost results need an explicit charged-retry confirm; keys/limits are Owner-only cards on /settings (guests make no requests).

- 2026-10-13 — LLM models: one composable (no store); the default is chosen once on /settings (auto-save select, "Use app default" as an item) and every AI call uses it, so no per-run model or profile card; usage counts the default model, which the notice names.
- 2026-10-12 — Tailored CV flow: Generate PDF saves first; a PDF is current when created after the last save (server timestamps), then the bar offers Preview + Apply instead of another PDF; latest PDF derived from the listing's newest unsent CV (uploads count too, API can't tell).
- 2026-10-12 — Tailored CV: full page, not part of Apply; built-in analysis runs one `analyzeTailoredCvSection` per section (not `analyzeAllTailoredCv`) for real progress; AI is opt-in per whole CV or section (built-in vs external choice); output fills only a new unedited candidate, otherwise waits as Accept/Dismiss suggestions.
- 2026-10-12 — Profile is read-first: cards are read-only with a ⋮ menu per row; bullets and target locations are edited in their forms but still save immediately (labelled), Cancel never undoes them.
- 2026-10-12 — CV review blockers show as warnings until the first Save attempt; Save stays clickable and focuses the first issue; disabled Save uses neutral-subtle, not inline styles.
- 2026-10-12 — CV import keeps candidates local until one reviewed atomic save; manual IDs select updates, links/hobbies require explicit replacement opt-in, and imported English sources preserve Norwegian translations.

- 2026-10-11 — Collected jobs use a separate Check jobs step so counts are visible and Copy prompt stays on a direct click.
- 2026-10-11 — Built-in collected parsing is sequential; invalid replies pause for a user decision, progress counts successful inputs only, and replacement/navigation confirms before losing prepared work or unsaved drafts.

- 2026-10-10 — Quick-add after save: flagged rows first in full, clean ones in a closed `UCollapsible` receipt list; one primary Compare per duplicate note (modal switches matches).
- 2026-10-10 — Quick-add has no submit button (Save calls `form.submit()`), so Enter can't save the batch; no Done/Cancel, leave action named by destination.
